X で「温泉オントロジー」というキーワードが流れてきました。面白そうだったのでコードと検証記事を読みました。コードは GitHub の [kazuhitogo/onsentology](https://github.com/kazuhitogo/onsentology)、検証は Qiita の [温泉オントロジーを作って「整理されたデータ」の意味を測る](https://qiita.com/kazuneet/items/8b890ba7903326209729) です。

オントロジーという言葉はよく聞くようになってきました。どういうところで必要になるのかを体感している人は、まだ少ない印象です。元記事のデータをそのまま使い、質問だけ変えて、どこからオントロジー側が要るかを見ていきます。比較は次の 3 条件で行いました。

| 表での呼び方 | 元の条件              | モデルに渡すもの                                 |
| ------------ | --------------------- | ------------------------------------------------ |
| 素の LLM     | A                     | 温泉の知識人という役割だけ。数値も一覧も渡さない |
| 揃えた MD    | F                     | グラフと同じ事実を同じ書式で並べた MD を検索する |
| オントロジー | G（ツールを直した版） | 施設や源泉の値を返すツール。数値は戻り値だけ使う |

## 温泉オントロジーの記事を読んで感じた違和感

環境省の掲示基準と施設の公表ページを Turtle（RDF をテキストで書く形式）にし、LLM にツールで数値を引かせる実験です。元の記事の観点は「データの整理が重要」に近いです。整理されたデータなら答えやすくなる。Turtle でも MDファイルでも大差ないということでした。

しっくり来なかった点は 2 つです。

ひとつは質問セットです。ホームページ 1 枚を読めば足りるものが多く、オントロジーの効果を見る場所としては、MDファイルで十分答えられる質問に見えました。

もうひとつは表現です。RDF でこれやるのか、と感じました。トリプル（主語・述語・目的語の 3 つ組）を見ると、次の点が気になります。

1. **加水や消毒が無名のノードになっている。** 施設の下に湯使い（加水・消毒など）の記録が大量についています。名前がないので、あとから「金の湯の加水」として引きにくいです。
2. **長い説明文が項目に残っている。** 数値や真偽に落ちておらず、構造化が途中です。
3. **クラスと個体の境が曖昧。** 塩化物泉などの泉質クラスを、源泉の値として直接つないでいます。

TTL の直しは今回しません。データセットも形式もそのままで、質問だけ変えます。Property Graph の方が同じ動きを組みやすい点は、後半で触れます。

## 元の12問は揃えた MD で足りる

元の記事の 12 問は次のとおりです。ホームページ 1 枚を読めば足りるものが多く、データを揃えた MD でも答えられます。

1. 草津の湯畑源泉の pH はいくつじゃ
2. 草津は源泉ごとに湯が違うと聞いた。湯畑・万代・煮川で pH はどう違うんじゃ
3. 有馬の金の湯はかけ流しかい
4. 高血圧の薬を飲んどるんじゃが、草津の湯に入ってよいかのう
5. 玉川温泉の湯は飲めるかい。1日どれくらいまでじゃ
6. 草津の大滝乃湯は、どんな症状に向くと掲示基準では言っておるんじゃ
7. 酸性の強い湯に入ったあと、仕上げにはどんな湯がええんじゃ
8. 草津で3日、1日2回で湯を回りたい。順番を組んでくれ
9. 加水も加温も循環ろ過も消毒もしとらん湯はあるかい
10. 秋保温泉の pH を教えてくれ
11. 玉川温泉は放射能泉なのかい。酸性泉でもあるのじゃろ
12. 美肌とデトックスができる湯はどこじゃ

元の記事の公開数字をそのまま紹介します。揃えた MD と、当時のオントロジー条件を 3 回ずつ回しています。

| モデル     | 素の LLM | 揃えた MD | オントロジー |
| ---------- | -------- | --------- | ------------ |
| Haiku 4.5  | 34.3%    | 88.2%     | 71.6%        |
| Sonnet 4.6 | 44.1%    | 95.1%     | 92.2%        |

揃えた MD はオントロジーと同じか、それ以上です。12 問では探している情報が同じページ近くにあるので、グラフから同じ書式に揃えた文章を渡せば足ります。Sonnetではオントロジーを使っても効果がなさそうな結果になっています。

オントロジーがあっても、一覧を集計できるモデルとできないモデルがいます。揃えた MD でも Haiku では厳しく、Sonnet なら通る質問を 1 問足しています。

## Haiku では厳しく、Sonnet なら揃えた MD で通る質問

今回のデータの温泉施設は全部で 15 件です。有馬の金の湯のページには加水（源泉に水を足すこと）と塩素消毒が書いてあります。銀の湯も加水と消毒がありますが、記載されているページが異なります。泉質が塩化物泉かどうかはまた別の項目です。施設をまたいで件数を出す必要があります。

追加した質問はこちらです。

> データセット内で「加水あり」かつ「消毒あり」の施設の件数と割合を出せ。そのうち泉質名に「塩化物泉」が含まれるものは何件か。

求められる回答は次のとおりです。

- 加水かつ消毒: 2 件（金の湯、銀の湯）
- うち塩化物泉: 1 件（金の湯）

揃えた MD とオントロジーで、各モデル 3 回の平均です。

| モデル     | 素の LLM | 揃えた MD | オントロジー |
| ---------- | -------- | --------- | ------------ |
| Haiku 4.5  | 0%       | 0%        | 33%          |
| Sonnet 4.6 | 0%       | 100%      | 100%         |

Haiku は揃えた MD でも 3 回とも数え切れませんでした。オントロジーでも 3 回中 1 回だけ 100% です。Sonnet は揃えた MD でもオントロジーでも 3 回とも 100% でした。15 施設が同じ欄に並んでいれば、Sonnet は文章から足し引きできます。Haiku 4.5 は同じ揃えた MD でも集計で止まります。ここまでだと、Sonnet 4.6 には揃えた MD で足りるように見えます。

## Sonnet でも、揃えた MD ではわからない質問

揃えた MD は施設ページから作っています。施設に付いていない源泉は 1 行もありません。Sonnet 4.6 でも、ページに無い行は読めません。

このデータには源泉が 28 本あります。うち 22 本は 15 施設のどれかに付いています。残り 6 本は、造成泉・供給専用の源泉・掲示基準の計算例・大涌谷の自噴など、どの施設ページにも出てこない源泉です。成分分析で裏付けられた泉質を持つのは大涌谷だけですが、大涌谷も施設に付いていないので揃えた MD には現れません。

この 3 問では、オントロジー側に源泉の全件一覧（`list_spring_sources`）と、測定由来と掲示名由来を分けて返す源泉詳細を足しています。値は元の TTL にあります。足したのは引き出しです。

いまの揃えた MD は施設ページから作っているので、未紐づきの源泉も由来の型もコーパスにありません。ここに源泉 28 本の一覧と紐づき・由来を書けば、Sonnet なら MD でも追える可能性が高いです。今回はその一覧を足していません。一覧を MD にコピーし続けると、更新漏れの話に戻ります。

追加した 3 問は次のとおりです。

1. **施設に付いていない源泉を列挙。** どの温泉施設のページからも参照されていない源泉をすべて挙げる。正解は 6 本。
2. **源泉の総数と内訳。** 登録されている源泉は全部で何本か。施設に付いている本数と、付いていない本数も言う。正解は 28 本＝22＋6。
3. **分析で裏付けられた泉質はどれか。** 掲示泉質名からの読み取りではなく、成分分析（測定）で裏付けられた泉質を持つ源泉はどれか。正解は大涌谷の酸性泉だけ。

揃えた MD とオントロジーで 3 回ずつ比べました。表の数字は、採点項目のうち通った割合の平均です。揃えた MD の 25% や 33% は部分点で、上の正解そのものには 3 回ともなっていません。

| 質問                           | Haiku<br>揃えたMD | Haiku<br>オントロジー | Sonnet<br>揃えたMD | Sonnet<br>オントロジー |
| ------------------------------ | ----------------- | --------------------- | ------------------ | ---------------------- |
| 施設に付いていない源泉を列挙   | 25%               | 83%                   | 25%                | 100%                   |
| 源泉の総数と内訳               | 25%               | 42%                   | 33%                | 100%                   |
| 分析で裏付けられた泉質はどれか | 33%               | 100%                  | 44%                | 100%                   |

Sonnet でも、揃えた MD では 3 回とも 6 本の列挙・28 本の内訳・大涌谷の特定には至りませんでした。オントロジーなら Sonnet は 3 問とも 3 回とも採点項目をすべて通しました。Haiku でも「分析由来は大涌谷だけ」は 3 回とも取れました。源泉 28 本の内訳は Haiku だと一覧を見ても数え間違えることがあり、3 回中 1 回だけ正解です。

## オントロジーが必要になる境界

社内システムに置き換えると、境界はダッシュボードに出ているかどうかです。画面にすでに出ている数字は、欄を揃えた MD でも足ります。元の 12 問がそれです。ダッシュボードには載っていないが知りたいこと、例えば画面に出てこない源泉の列挙や測定由来は、施設ページを増やしても出てきません。今回の追加 3 問がそれです。ここはオントロジーを知識基盤として使う場所です。

MD に関係を散らすと、同じ事実が複数ファイルにコピーされます。AI が苦手な Data Scatter（事実が文書のあちこちに散っている状態）と、直したつもりが他ファイルに残る更新漏れが同時に起きます。ナレッジグラフをグラフ DB に置くと、エンティティやエッジを 1 か所直せば、それを辿る照会は新しい値を見ます。件数が増えるほど、この差は大きくなります。

| 状況                                               | どうするか                           |
| -------------------------------------------------- | ------------------------------------ |
| ダッシュボードや構造化されたMDファイルに答えがある | 揃えた MD で足りる（元の 12 問）     |
| 件数の足し引きを Haiku でも安定させたい            | 件数は検索せず、ツールの戻り値で返す |
| 画面に無い対象や、無いこと・由来を数え切る         | オントロジーが要る（追加 3 問）      |
| 関係が複数ファイルに散る。規模が増える             | エンティティとエッジを 1 か所直す    |

今回の実装は RDF（Turtle）です。グラフに事実があっても、引き出しが施設名だけだと一覧や除外は見えません。一覧や由来の型まで渡すと、今回の 3 問のように見えてきます。この引き出しをエージェントに渡す動きは、Property Graph の方が組みやすいです。ノードとエッジに属性を載せて Cypher で辿る形です。RDF との違いは [RDF vs Property Graph](https://zenn.dev/knowledge_graph/articles/rdf-vs-property-graph-2025) に書いています。

## 同じように試すときの質問

[onsentology](https://github.com/kazuhitogo/onsentology) に、次の文言をそのまま渡せます。揃えた MD とオントロジーの 2 条件で回してください。

**Haiku では厳しく、Sonnet なら揃えた MD で通る**

1. データセット内で「加水あり」かつ「消毒あり」の施設の件数と割合を出せ。そのうち泉質名に「塩化物泉」が含まれるものは何件か。

**Sonnet でも揃えた MD ではわからない**

1. 登録されている源泉のうち、どの温泉施設のページからも参照されていない（どの施設にも紐づかない）源泉をすべて挙げよ。
2. このデータに登録されている源泉は全部で何本か。施設に紐づく源泉と、どの施設にも紐づかない源泉の内訳も示せ。
3. このデータで、掲示泉質名からの読み取りではなく、成分分析（測定）で裏付けられた泉質を持つ源泉はどれか。あるなら源泉名と泉質を挙げよ。

## 測り方のメモ

Turtle は元の記事のままです。変えたのは質問と、上で書いたオントロジー側の引き出しです。テキスト側は、グラフの施設まわりと同じ事実を同じ書式で並べた MD（揃えた MD）を使いました。施設ページ由来のままなので、源泉の全件一覧や由来の型はコーパスに入れていません。

追加した 4 問は各モデル 3 回です。採点は正規表現です。言い回しで落ちる場合があります。件数や除外で検索が崩れやすい話は [RAGなしで始めるナレッジグラフQA](https://zenn.dev/knowledge_graph/articles/kg-no-rag-starter) にあります。
